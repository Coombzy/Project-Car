## What was checked and found sound

- **Migrations:** one line from `20260816_0001` to `20261105_0019` with a single head. On Postgres 16, upgrade, downgrade to base and upgrade again all succeed. `alembic check` and a type and server-default comparison find zero differences, and every model CHECK constraint exists in the database.
- **Postgres smoke test:** after `python -m app.seed --reset`, every owner and member read route I called returned 200.
- **Test suites:** API pytest passes 452 tests in 34 s; web typecheck is clean; 157 web unit tests pass; `next build` passes.
- **Route coverage:** every API route has at least one direct test call, and branch coverage is 90%.
- **Accessibility:** 44 of 50 scanned page views have no WCAG 2.1 A or AA violations.
- **Double booking:** prevented in the database by the unique `(hoist_id, hour_start)` constraint on `booking_hours`.
- **Repeated refund accepts (backlog R100):** no longer double-credit. `cancel_booking` re-reads the booking under a row lock, and the one-refund-per-booking partial unique index (`20261105_0017`) rejects a second refund.
- **Sessions and secrets:** sessions are signed and expire. Member tokens carry a password fingerprint. scrypt parameters are bounded, and secrets are compared in constant time.
- **Landed security rows:** startup refuses placeholder secrets outside dev mode (#332); the API docs are hidden outside dev mode; security headers are set on API responses (#335); credentialed CORS is limited to ops and app origins (#334); login buckets are per realm (#343).
- **Python dependencies:** `pip-audit` finds no known vulnerability in the resolved API dependencies.
