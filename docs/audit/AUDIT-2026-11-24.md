# Project Car / Shop OS audit, 2026-11-24

- **Audited commit:** `82de276` on `main` (2026-11-24, "Count login failures per realm and client IP (#343)").
- **Scope:** the API in `apps/project-car/api`, the web app in `apps/project-car/web`, both test suites, `.github/workflows/shop-os-ci.yml`, `infra/compose`, `scripts/cursor-install.sh`, and the specs in `Docs/`.
- **Method:** I read the code and reproduced each behavior-level finding against the real app: FastAPI TestClient on in-memory SQLite (same wiring as `tests/conftest.py`), a local Postgres 16, and the built web app with an axe-core scan. Commands and results are in [Verification log](#verification-log). Anything I could only infer is not reported as a finding.
- **Paths:** paths in the tables are relative to `apps/project-car/`. Paths starting with `Docs/`, `.github/`, `infra/` or `scripts/` are relative to the repo root.

## Summary

The core holds up well under checking. The Alembic chain is linear and clean on real Postgres, with no model drift. All 452 API tests and 157 web unit tests pass, and branch coverage is 90%. The October security rows that landed (secret guard, hidden docs, CORS split, security headers, per-realm login buckets) work as described.

The serious problems sit in two places: the money-adjacent features added in November, and who is allowed to do what.

- Any member can credit themselves any number of tokens for any price through the stand-in purchase route.
- The AI bearer can set a member's password, sign in as that member and buy tokens. It can reserve a member's tokens without approval. `Docs/ai-control.md` forbids both. It can also grant allowances that the API otherwise keeps for a human.
- A fresh database opens public self-serve signup, and any visitor can take a Premium allowance for free. The app spec lists both as out of v1.
- On the FastAPI version a fresh install resolves, every write commits after the response has already been sent.

Also high: `next@15.5.25` carries a critical advisory, and the web never forwards the browser's IP. Because of the second, anyone can lock every owner out of login for 15 minutes.

There are 64 findings: 1 critical, 5 high, 26 medium and 32 low. Each is sized to fit one PR of 150 changed lines or fewer, or split into numbered parts. Twenty-two cite an existing row in `Docs/backlog.md`: for 17 the row already plans the whole fix, and for 5 it covers part of it. I re-checked each of those as still open on `82de276`.

## Top 10

1. **PC-AUD-001 (critical).** `POST /member/token-purchases` takes both `tokens` and `amount_cad` from the member. Verified: 999,999 tokens credited for $0.01.
2. **PC-AUD-009 (high).** The AI bearer can set member passwords, then sign in as the member and buy tokens, and it can reserve a member's tokens without approval. `Docs/ai-control.md` forbids both. It can also create members with a free allowance, although the API keeps the monthly grant for humans.
3. **PC-AUD-011 (high).** Fresh databases default to public self-serve signup, and any tier can be picked. Verified: an anonymous visitor got a Premium account with 1,500 tokens. App spec §4 lists self-serve signup as out of v1.
4. **PC-AUD-002 (high).** `get_db` commits after the response is sent. Verified on FastAPI 0.165.0, which a fresh install resolves. Clients get a 2xx before their write is durable, and the web's create-then-confirm flow can race the commit.
5. **PC-AUD-012 (high).** `next@15.5.25` falls inside a critical advisory and a Server Actions DoS advisory. Both are fixed in 15.5.29.
6. **PC-AUD-010 (high).** The web sends no client IP to the API, so every web login shares one rate-limit bucket. Eight bad owner logins from anyone lock the owner out.
7. **PC-AUD-003 (medium).** The next-day fill discount is applied to every hour of a booking that touches tomorrow's window. Verified: 150.00 instead of 168.75. The per-hour code exists but cannot run.
8. **PC-AUD-004 (medium).** Concurrent approve and deny on one parts request both succeed on Postgres: 17 of 20 trials. This is backlog R105.
9. **PC-AUD-045 (medium).** Quotes have no length cap. Any member can request a multi-year quote; two years took 1.65 s and returned 2.8 MB.
10. **PC-AUD-013 (medium).** Owner sessions cannot be revoked; a logged-out cookie still works for 24 h. This is backlog R118.

## How to read the tables

- **Severity.** Critical: an ordinary user can exploit it now, or it corrupts the token ledger or money records. High: a security exposure or data-correctness bug with a clear path to harm. Medium: a real defect with limited blast radius or a precondition. Low: hygiene, latent risk or polish.
- **Effort.** S is up to about 60 changed lines, M is about 60–150, and L means the item is split into parts, each 150 lines or fewer.
- **Door.** One-way means hard to reverse once shipped: a schema migration, deleted data, or a contract that clients rely on. Two-way means easy to revert.
- **Needs owner value** marks a value only Ben can supply. The fix text names the stand-in to build against meanwhile.
- **Owner-only** marks work that edits `.github/workflows/**`, which agents may not touch under `AGENTS.md`.
- **Backlog** names an existing row in `Docs/backlog.md` that already plans the fix. Those rows are still open on `82de276` unless the table says otherwise.
